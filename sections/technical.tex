\section{Standortinformationen}
\label{sec:location-metric}

In dieser Arbeit werden unter Standortinformationen solche Informationen
verstanden, die einen Standort technisch beschreiben und allgemeine,
standortbezogene Eigenschaften zusammenfassen, die nicht unmittelbar
einem einzelnen System oder Gerät zuzuordnen sind. Sie ergänzen die in
den folgenden Abschnitten beschriebenen Netzwerk- und Systemmetriken
um Kontextinformationen zum jeweiligen Standort.

Dabei werden insbesondere Informationen berücksichtigt, die für die
eindeutige Identifikation, Klassifikation und geografische Einordnung
eines Standorts relevant sind. Diese Informationen ermöglichen es,
Standorte eindeutig zuzuordnen und auf einer Weltkarte darzustellen.
Zusätzlich wird der Status der zugrunde liegenden Datenquellen erfasst,
um nachvollziehen zu können, ob die Standortinformationen vollständig
und fehlerfrei abgerufen werden konnten.

\begin{compactitem}
    \item \textbf{Ländercode:} Der Ländercode gibt die Länderzuweisung eines
    Standorts nach dem Standard \gls{iso3166}~\cite{iso2026countrycodes} an.

    \item \textbf{Geografische Position:} Beschreibt die geografischen Koordinaten
    eines Standorts. Sie ermöglichen die eindeutige geografische Zuordnung und
    die Darstellung des Standorts auf einer Weltkarte.

    \item \textbf{Klassifikation:} Die Klasse eines Standorts lässt sich in
    folgende Kategorien unterteilen:
    \begin{compactitem}
        \item Cloud Hub
        \item Hub
        \item Remote Site
        \item Small Site
        \item Medium Site
        \item Large Site
        \item Special Site
    \end{compactitem}

    \item \textbf{Abrufstatus je Datenquelle:} Beschreibt für jede der zugrunde
    liegenden Datenquellen, ob die benötigten Standortinformationen erfolgreich
    abgerufen werden konnten oder bei der Erfassung ein Fehler aufgetreten ist.
\end{compactitem}

\section{Netzwerkmetriken}
\label{sec:netzwerkmetriken}

Netzwerkmetriken beschreiben den aktuellen Zustand und die Leistungsfähigkeit
eines Netzwerks. Sie ermöglichen eine Bewertung der Netzwerkkommunikation
und können dazu beitragen, potenzielle Probleme und Abweichungen frühzeitig
zu erkennen~\cite{aruba2026userguide}.

Für die Darstellung im Plugin wurden solche Netzwerkmetriken ausgewählt,
die einen schnellen Überblick über den Zustand der Netzwerkinfrastruktur
eines Standorts ermöglichen. Die nachfolgend beschriebenen Werte geben
dabei einen kompakten Überblick über wesentliche Aspekte der
Netzwerkumgebung, ohne dass hierfür die einzelnen Systeme und deren
detaillierte Zustände betrachtet werden müssen. Dadurch können
beispielsweise die Leistungsfähigkeit, Verfügbarkeit und vorhandene
Redundanz eines Standorts auf einen Blick eingeschätzt werden.

Die ausgewählten Metriken bilden damit die Grundlage für eine
übersichtliche Darstellung des Netzwerkzustands auf Standortebene.
Zusätzlich werden die entsprechenden Einzelwerte der überwachten Systeme
erfasst, um bei Bedarf eine detailliertere Betrachtung der
Netzwerkinfrastruktur zu ermöglichen.

\subsection{Aggregierte Standortwerte}
\label{subsec:netzwerk-aggregierte-werte}

Die folgenden Metriken stellen aggregierte Werte auf Standortebene dar.
Sie werden aus den einzelnen Netzwerkmetriken der einem Standort
zugeordneten Systeme ermittelt. Die Aggregation dient dazu, den Zustand
der Netzwerkinfrastruktur eines Standorts unabhängig von der Anzahl der
einzelnen überwachten Systeme kompakt darzustellen. Die Aggregation von 
Messwerten dient der Verdichtung großer Datenmengen und ermöglicht die 
Darstellung komplexer Systemzustände in komprimierter Form \cite{wen2020aggregation}.

\begin{compactitem}
    \item \textbf{Bandbreite:} Die durchschnittliche Bandbreite beschreibt die
    durchschnittliche Datenübertragungsrate, die über ein Interface innerhalb
    eines bestimmten Zeitraums beim Senden oder Empfangen von Daten erreicht
    wird \cite{aruba2026userguide}.

    \item \textbf{Latenz:} Die Latenz beschreibt die Zeit, die Daten für
    die Übertragung zwischen zwei Geräten benötigen~\cite{aruba2026userguide}.

    \item \textbf{Erreichbare Geräte:} Die Anzahl der erreichbaren
    \glspl{silverpeak} an einem Standort~\cite{aruba2026userguide}.

    \item \textbf{Nichterreichbare Geräte:} Die Anzahl der nicht erreichbaren
    \glspl{silverpeak} an einem Standort~\cite{aruba2026userguide}.

    \item \textbf{Primäre WAN-Verbindungen:} Die Anzahl der als primär
    konfigurierten \glspl{wan}, über die der reguläre Datenverkehr eines
    Standorts geleitet wird.

    \item \textbf{Backup-WAN-Verbindungen:} Die Anzahl der als Backup
    konfigurierten \glspl{wan}, die im Falle eines Ausfalls der primären
    Verbindung den Datenverkehr übernehmen.
\end{compactitem}

\subsection{Einzelwerte}
\label{subsec:netzwerk-einzelwerte}

\paragraph{SD-WAN System}
\label{par:sd-wan-values}

~

Die folgenden Werte werden für jedes einzelne \gls{sdwan}-System erfasst.
Sie beschreiben die Eigenschaften und den aktuellen Zustand des jeweiligen
Systems. Einzelne dieser Werte, insbesondere die Erreichbarkeit und der
WAN-Status, bilden die Grundlage für die Berechnung der aggregierten
Standortwerte (siehe Abschnitt~\ref{subsec:netzwerk-aggregierte-werte}).

\begin{compactitem}
    \item \textbf{Name:} Eindeutige Bezeichnung des \gls{sdwan}-Systems.

    \item \textbf{Typ:} Beschreibt die Art des überwachten Systems,
    beispielsweise SD-WAN-Router.

    \item \textbf{LAN-IP-Adresse:} Die interne IP-Adresse des Systems
    innerhalb des lokalen Netzwerks.

    \item \textbf{WAN-IP-Adresse:} Öffentliche beziehungsweise
    externe IP-Adresse der WAN-Schnittstelle.

    \item \textbf{Firmware-Version:} Version der auf dem System
    installierten Software beziehungsweise Firmware.

    \item \textbf{Erreichbarkeit:} Gibt an, ob das System aktuell über
    das Netzwerk erreichbar ist.

    \item \textbf{WAN-Status:} Beschreibt den aktuellen Status beziehungsweise
    die Rolle der WAN-Verbindung, beispielsweise als primäre oder
    Backup-WAN-Verbindung.
\end{compactitem}

\paragraph{Virtuelle Netzwerke}
\label{par:virtuel-networks}

~

Die folgenden Werte werden zur Identifikation und Einordnung eines virtuellen
Netzwerks sowie zur zeitlichen Nachvollziehbarkeit seiner Erfassung verwendet.
Sie werden aus den bereitgestellten Datenquellen ermittelt, die in
Abschnitt~\ref{sec:defined-sources} beschrieben sind. Die ausgewählten Werte
ermöglichen dabei sowohl die eindeutige Zuordnung eines virtuellen Netzwerks
als auch die Einordnung der zugehörigen Ressourcen und die Nachvollziehbarkeit
des Erfassungszeitraums.

\begin{compactitem}

    \item \textbf{Name:} Der festgelegte Name eines virtuellen Netzwerks.
    Er dient zur eindeutigen Identifikation und Zuordnung des virtuellen
    Netzwerks innerhalb der dargestellten Infrastruktur.

    \item \textbf{Ressourcengruppe:} Die dem virtuellen Netzwerk zugewiesene
    Ressourcengruppe, über die zusammengehörige Ressourcen logisch gruppiert
    und verwaltet werden. Sie ermöglicht die Zuordnung des virtuellen Netzwerks
    zu den weiteren zugehörigen Ressourcen.

    \item \textbf{Firstseen:} Der Zeitpunkt, zu dem das virtuelle Netzwerk
    erstmals erfasst wurde. Dieser Wert ermöglicht die zeitliche Einordnung
    des virtuellen Netzwerks und gibt Aufschluss darüber, seit wann es in den
    erfassten Daten vorhanden ist.

    \item \textbf{Lastseen:} Der Zeitpunkt, zu dem das virtuelle Netzwerk
    zuletzt erfasst wurde. Dadurch kann nachvollzogen werden, wann das
    virtuelle Netzwerk zuletzt in den bereitgestellten Datenquellen
    festgestellt wurde.
    
\end{compactitem}

\paragraph{Netzwerkgruppe}
\label{par:network-group}

Eine \gls{nsg} filtert den ein- und ausgehenden Netzwerkverkehr von Azure-Ressourcen
anhand einer Menge von Sicherheitsregeln \cite{microsoft2026nsg}. Die folgenden
Werte werden erfasst, da sie die Konfiguration und Wirkung einer Sicherheitsregel
beschreiben.

\begin{compactitem}

    \item \textbf{Name:} Der eindeutige Name der Sicherheitsregel
    \cite{microsoft2026nsg}. Er ermöglicht die Identifikation der Regel.

    \item \textbf{Richtung:} Gibt an, ob die Regel für ein- oder ausgehenden
    Datenverkehr gilt \cite{microsoft2026nsg}:
    \begin{compactitem}
        \item Inbound
        \item Outbound
    \end{compactitem}
    Dadurch lässt sich die Kommunikationsrichtung der Regel bestimmen.

    \item \textbf{Zugriffsart:} Legt fest, ob Datenverkehr zugelassen oder
    blockiert wird \cite{microsoft2026nsg}. Sie zeigt die Wirkung der Regel.

    \item \textbf{Protokoll:} Das von der Regel betroffene Netzwerkprotokoll,
    beispielsweise TCP, UDP, ICMP oder Any \cite{microsoft2026nsg}.
    Dadurch lässt sich die betroffene Kommunikation genauer bestimmen.

    \item \textbf{Quelle:} Die IP-Adresse, das CIDR-Suffix oder der Dienst-Tag,
    von dem der Datenverkehr ausgeht \cite{microsoft2026nsg}.
    Sie zeigt, von welcher Quelle die Kommunikation ausgeht.

    \item \textbf{Quellport:} Der Port oder Portbereich, von dem der
    Datenverkehr ausgeht. Dadurch lässt sich die betroffene Kommunikation
    genauer eingrenzen.

    \item \textbf{Ziel:} Die IP-Adresse, das CIDR-Suffix oder der Dienst-Tag,
    an den der Datenverkehr gerichtet ist \cite{microsoft2026nsg}.
    Dadurch lässt sich das Ziel der Kommunikation bestimmen.

    \item \textbf{Zielport:} Der Port oder Portbereich, an den der
    Datenverkehr gerichtet ist. Er ermöglicht eine genauere Bestimmung
    des betroffenen Netzwerkdienstes.

    \item \textbf{Standardregel:} Gibt an, ob die Regel von Azure automatisch
    angelegt wurde \cite{microsoft2026nsg}. Dadurch kann zwischen
    Standard- und eigenen Regeln unterschieden werden.

    \item \textbf{Status:} Gibt an, ob die Regel aktuell aktiv ist.
    Dadurch lässt sich erkennen, ob die Regel derzeit wirksam ist.

\end{compactitem}

\section{Systemmetriken}
\label{sec:systemmetriken}

Systemmetriken beschreiben den aktuellen Zustand und die Ressourcennutzung
eines Systems. Sie ermöglichen eine Einschätzung der Auslastung und des
Zustands der überwachten Systeme.

\subsection{Aggregierte Standortwerte}
\label{subsec:system-aggregierte-werte}

Die folgenden Metriken stellen aggregierte Werte auf Standortebene dar.
Sie werden aus den Werten der einzelnen Systeme eines Standorts ermittelt,
um eine kompakte Bewertung des Systemzustands eines Standorts zu ermöglichen.

\begin{compactitem}

    \item \textbf{Problemanzahl:} Die Problemanzahl beschreibt die Anzahl der
    aktuell auf einem System erkannten Probleme \cite{zabbix2026problemget}.
    Sie ermöglicht eine schnelle Einschätzung des aktuellen Problemzustands
    eines Standorts.

    \item \textbf{Anzahl fehlender Softwareaktualisierungen:} Diese Metrik
    beschreibt die Anzahl der fehlenden Softwareaktualisierungen.
    Sie zeigt den Aktualisierungsbedarf der Systeme eines Standorts.

    \item \textbf{Isolierte Systeme:} Diese Metrik beschreibt die Anzahl der
    Systeme, die vom restlichen Netzwerk isoliert wurden.
    Sie ermöglicht die Erkennung von Systemen mit eingeschränktem Zugriff.

    \item \textbf{Anzahl an Systemen:} Diese Metrik beschreibt die Anzahl der
    an einem Standort vorhandenen Systeme und Systemressourcen.
    Sie ermöglicht eine Übersicht über die Größe der Systemlandschaft.

    \item \textbf{Geräteanzahl pro Typ:} Diese Metrik beschreibt die Anzahl
    der an einem Standort vorhandenen Geräte, gruppiert nach Gerätetypen.
    Sie ermöglicht eine Übersicht über die Zusammensetzung der
    Geräteinfrastruktur.

\end{compactitem}

\subsection{Einzelwerte}
\label{subsec:system-einzelwerte}

Die folgenden Werte werden für die einzelnen Systeme und Geräte eines
Standorts erfasst. Sie ermöglichen eine detaillierte Bewertung des Zustands
und der Ressourcennutzung einzelner Systeme.

\paragraph{HCI Information}
\label{par:hci-information}

Die folgenden Werte beschreiben Metriken eines \gls{hci}-Systems, die zur
Bewertung dessen Zustands und Ressourcenauslastung herangezogen werden.

\begin{compactitem}

    \item \textbf{CPU-Auslastung:} Beschreibt den Anteil der verfügbaren
    Rechenleistung, der von einer \gls{hci} aktuell genutzt wird
    \cite{microsoft2026troubleshoot}. Sie ermöglicht die Erkennung einer
    hohen CPU-Auslastung.

    \item \textbf{RAM-Auslastung:} Beschreibt die aktuelle Nutzung des
    verfügbaren Arbeitsspeichers einer \gls{hci}
    \cite{microsoft2026troubleshoot}. Sie ermöglicht die Bewertung der
    Speicherauslastung.

    \item \textbf{Speicherauslastung:} Beschreibt den Anteil des verfügbaren
    Massenspeicherplatzes, der aktuell genutzt wird
    \cite{microsoft2026troubleshoot}. Sie zeigt den aktuellen
    Speicherbedarf des Systems.

    \item \textbf{Datenspeicher-Auslastung:} Beschreibt den Anteil des
    verfügbaren Datenspeichers einer \gls{hci}, der aktuell genutzt wird.
    Sie ermöglicht die Erkennung einer hohen Auslastung des Datenspeichers.

    \item \textbf{Speicherbereitstellung:} Beschreibt den Anteil der insgesamt
    verfügbaren Speicherkapazität, der von einer \gls{hci} bereitgestellt
    beziehungsweise genutzt wird. Sie ermöglicht die Bewertung der
    verfügbaren und bereitgestellten Kapazität.

    \item \textbf{Genutzte vSAN-Kapazität:} Beschreibt die aktuell belegte
    Speicherkapazität innerhalb des \gls{vsan}-Verbunds. Sie ermöglicht die
    Bewertung der aktuellen Kapazitätsauslastung.

\end{compactitem}

\paragraph{HCI Konfigurationsdaten}
\label{par:hci-configurationdata}

Die folgenden Werte beschreiben statische Konfigurations- und
Hardwareeigenschaften eines \gls{hci}-Systems. Sie werden erfasst, um
die technische Ausstattung, Kapazität und Konfiguration eines Systems
einordnen zu können.

\begin{compactitem}

    \item \textbf{\gls{raid}-Stufe:} Beschreibt die verwendete Redundanz-
    und Speicherstrategie des HCI-Systems. Sie ermöglicht die Einordnung
    der vorhandenen Ausfallsicherheit.

    \item \textbf{Anzahl der \gls{hci}-Knoten:} Beschreibt die Anzahl der
    physischen Knoten der HCI-Infrastruktur. Sie ermöglicht die Bewertung
    der Größe des HCI-Verbunds.

    \item \textbf{Anzahl virtueller Maschinen:} Beschreibt die Anzahl der
    auf der HCI betriebenen virtuellen Maschinen. Sie zeigt den Umfang
    der virtualisierten Umgebung.

    \item \textbf{CPU-Sockel pro Knoten:} Beschreibt die Anzahl der CPU-Sockel
    eines einzelnen HCI-Knotens. Dadurch lässt sich die CPU-Ausstattung
    eines Knotens einordnen.

    \item \textbf{Gesamtanzahl der CPU-Sockel:} Beschreibt die Gesamtanzahl
    der CPU-Sockel der HCI-Infrastruktur. Sie gibt einen Überblick über
    die verfügbare CPU-Hardware.

    \item \textbf{CPU-Kerne pro Sockel:} Beschreibt die Anzahl der Rechenkerne
    je CPU-Sockel. Dadurch lässt sich die Rechenleistung der eingesetzten
    CPUs genauer einordnen.

    \item \textbf{Gesamtanzahl der CPU-Kerne:} Beschreibt die Gesamtzahl der
    verfügbaren CPU-Kerne. Sie ermöglicht eine Übersicht über die gesamte
    Rechenkapazität der HCI-Infrastruktur.

    \item \textbf{Arbeitsspeicher pro Knoten:} Beschreibt die Größe des
    verfügbaren Arbeitsspeichers eines HCI-Knotens. Dadurch lässt sich
    die Speicherausstattung eines Knotens vergleichen.

    \item \textbf{Anzahl der Cache-Datenträger pro Knoten:} Beschreibt die
    Anzahl der für Caching verwendeten Datenträger je Knoten. Sie ermöglicht
    die Einordnung der Cache-Konfiguration.

    \item \textbf{Größe der Cache-Datenträger:} Beschreibt die
    Speicherkapazität der für Caching verwendeten Datenträger. Sie zeigt
    die verfügbare Cache-Kapazität.

    \item \textbf{Anzahl der Kapazitätsdatenträger pro Knoten:} Beschreibt
    die Anzahl der Datenträger für die dauerhafte Datenspeicherung je
    HCI-Knoten. Sie ermöglicht die Einordnung der Speicherkonfiguration.

    \item \textbf{Anzahl der Kapazitätsdatenträger pro Datenträgergruppe:}
    Beschreibt die Anzahl der Kapazitätsdatenträger innerhalb einer
    Datenträgergruppe. Dadurch lässt sich die Struktur der
    Datenträgergruppen nachvollziehen.

    \item \textbf{Größe der Kapazitätsdatenträger:} Beschreibt die
    Speicherkapazität der für die dauerhafte Datenspeicherung verwendeten
    Datenträger. Sie ermöglicht die Einordnung der verfügbaren
    Speicherkapazität.

    \item \textbf{Gesamtanzahl der Datenträger pro Knoten:} Beschreibt die
    Anzahl aller in einem \gls{hci}-Knoten vorhandenen Datenträger.
    Dadurch lässt sich die gesamte Laufwerksausstattung eines Knotens
    erfassen.

    \item \textbf{\gls{vsan}-Kapazität:} Beschreibt die insgesamt für den
    \gls{vsan}-Verbund verfügbare Speicherkapazität
    \cite{vmware2026vsan}. Sie ermöglicht die Bewertung der verfügbaren
    Gesamtkapazität des Verbunds.

\end{compactitem}

\paragraph{Serverinformationen}
\label{par:server-values}

Die folgenden Werte werden zur Bewertung des aktuellen Zustands und
der Verfügbarkeit eines Servers erfasst.

\begin{compactitem}

    \item \textbf{CPU-Auslastung:} Beschreibt den Anteil der verfügbaren
    Rechenleistung, der von einem Server aktuell genutzt wird
    \cite{microsoft2026troubleshoot}. Sie ermöglicht die Bewertung der
    aktuellen CPU-Auslastung.

    \item \textbf{RAM-Auslastung:} Beschreibt die aktuelle Nutzung des
    verfügbaren Arbeitsspeichers eines Servers
    \cite{microsoft2026troubleshoot}. Sie zeigt die Speicherauslastung
    des Servers.

    \item \textbf{Speicherauslastung:} Beschreibt den Anteil des verfügbaren
    Massenspeicherplatzes, der aktuell genutzt wird
    \cite{microsoft2026troubleshoot}. Sie ermöglicht die Erkennung einer
    hohen Speicherauslastung.

    \item \textbf{Defender-Status:} Beschreibt den aktuellen Betriebs- und
    Sicherheitsstatus des auf dem Server installierten Microsoft Defenders.
    Er ermöglicht die Bewertung des aktuellen Schutzstatus.

    \item \textbf{Zabbix-Status:} Beschreibt die aktuelle Verfügbarkeit und
    Erreichbarkeit eines Servers aus Sicht von Zabbix
    \cite{zabbix2026availability}. Er zeigt, ob der Server aktuell
    überwacht werden kann.

    \item \textbf{Zabbix-Probleme:} Beschreibt die Anzahl der aktuell von
    Zabbix für den Server erkannten Probleme
    \cite{zabbix2026problemget}. Sie ermöglicht eine schnelle Einschätzung
    des Problemzustands.

    \item \textbf{Anzahl fehlender Softwareaktualisierungen:} Beschreibt
    die Anzahl der fehlenden Softwareaktualisierungen. Sie zeigt den
    bestehenden Aktualisierungsbedarf des Servers.

    \item \textbf{Isolationsstatus:} Beschreibt, ob ein Server vom restlichen
    Netzwerk isoliert wurde. Er zeigt, ob die Netzwerkkommunikation des
    Servers eingeschränkt ist.

    \item \textbf{Isolationsart:} Beschreibt die Art der auf einen Server
    angewendeten Netzwerkisolierung. Sie ermöglicht eine genauere
    Einordnung der bestehenden Einschränkung.

\end{compactitem}

\paragraph{Geräteinformationen}

\label{par:device-info}

Die folgenden Werte werden zur Identifikation und Bewertung von Geräten
innerhalb der überwachten Netzwerkinfrastruktur erfasst.

\begin{compactitem}

    \item \textbf{Name:} Eindeutige Bezeichnung eines Netzwerkgeräts innerhalb
    der überwachten Infrastruktur. Sie ermöglicht die Identifikation des
    jeweiligen Geräts.

    \item \textbf{Gerätetyp:} Beschreibt die funktionale Kategorie eines
    Geräts. Dadurch lässt sich die Rolle des Geräts im Netzwerk einordnen.

    \begin{compactitem}
        \item Firewall
        \item Sensor
        \item Router
        \item Kamera
        \item Switch
        \item Access Point
    \end{compactitem}

    \item \textbf{Modell:} Beschreibt das konkrete Hardwaremodell eines
    Geräts. Es ermöglicht die technische Einordnung des Geräts.

    \item \textbf{LAN-IP-Adresse:} Die interne IP-Adresse eines Geräts
    innerhalb des lokalen Netzwerks. Sie ermöglicht die Zuordnung des
    Geräts innerhalb des Netzwerks.

    \item \textbf{Öffentliche IP-Adresse:} Die öffentliche beziehungsweise
    extern erreichbare IP-Adresse eines Geräts oder seines Internetzugangs.
    Sie ermöglicht die Identifikation des externen Netzwerkzugangs.

    \item \textbf{Status:} Beschreibt den derzeitigen Status eines
    Netzwerkgeräts. Er ermöglicht die Bewertung der aktuellen
    Verfügbarkeit des Geräts.

\end{compactitem}

\paragraph{Verbundene Endgeräte}

\label{par:device-clients}

Die folgenden Werte beschreiben Endgeräte, die mit einem Netzwerkgerät
verbunden sind. Sie ermöglichen die Identifikation und Zuordnung der
verbundenen Endgeräte innerhalb des Netzwerks.

\begin{compactitem}

    \item \textbf{IP-Adresse:} Die dem Endgerät aktuell zugewiesene
    IP-Adresse innerhalb des Netzwerks. Sie ermöglicht die Identifikation
    und Erreichbarkeit des Endgeräts.

    \item \textbf{MAC-Adresse:} Die eindeutige Hardwareadresse der
    Netzwerkschnittstelle des Endgeräts. Sie ermöglicht die eindeutige
    Zuordnung des Endgeräts.

    \item \textbf{VLAN:} Das virtuelle lokale Netzwerk, dem das Endgerät
    zugeordnet ist. Es ermöglicht die Einordnung des Endgeräts in die
    entsprechende Netzwerksegmentierung.

\end{compactitem}

\section{Zabbix}
\label{sec:zabbix}

\gls{zabbix} ist eine Open-Source-Monitoring-Software, mit der Server und
andere Systeme erfasst und deren Auslastung überwacht werden
können~\cite{zabbix2026about}. Darüber hinaus ermöglicht \gls{zabbix} über
Tags und Gruppen eine strukturierte Gruppierung der überwachten
Systeme~\cite{zabbix2026about}.

\subsection{Zabbix API}
\label{subsec:zabbix-api}

\gls{zabbix} verwendet \gls{jsonrpc} als Grundlage für die Kommunikation mit 
der API. Dabei werden Anfragen und Antworten im JSON-Format kodiert und über 
HTTP-POST-Anfragen an die API übermittelt~\cite{zabbix2026api}. Für die Authentifizierung 
stehen zwei Möglichkeiten zur Verfügung. Einerseits kann über die Methode \texttt{user.login} 
unter Angabe eines Benutzernamens und Passworts ein API-Token angefordert werden. Andererseits 
besteht die Möglichkeit, einen bereits über die Weboberfläche generierten, permanenten API-Token 
zu verwenden. Der verwendete Token muss anschließend bei jeder weiteren Anfrage mitgesendet werden, 
um auf die übrigen API-Endpunkte zugreifen zu können~\cite{zabbix2026api}.

Das Codebeispiel~\ref{lst:zabbix-request} zeigt eine Möglichkeit, wie die Host-Informationen abgerufen
werden können.

\begin{lstlisting}[language=Typescript, caption={Zabbix API Request}, label={lst:zabbix-request}]
const baseUrl = '...';
const apiToken = '...';

const request = {
    jsonrpc: '2.0',
    method: 'host.get',
    params: {
        output: ['hostid', 'host', 'name'],
        selectTags: 'extend',
        selectGroups: ['groupid', 'name']
    },
    auth: apiToken,
    id: 1
};

const response = await fetch(baseUrl, {
    method: 'POST',
    headers: {
        'Content-Type': 'application/json-rpc'
    },
    body: JSON.stringify(request)
});

const data = await response.json();
console.log(data.result);
\end{lstlisting}

\subsection{Silverpeak API}
\label{subsec:silverpeak-api}

\gls{silverpeakcompany} API stellt Informationen über \gls{rest} Endpunkte bereit. Die Authentifizierung erfolgt über ein \gls{sessioncookie}
und ein CSRF-Token welches 
bei nachfolgenden Anfragen mitgesendet werden muss, um den derzeitigen Zustand eines \gls{silverpeak} zu ermitteln~\cite{aruba2026userguide}.

Listing~\ref{lst:silverpeak-request} zeigt eine solche Anfrage, um den Zustand eines
\gls{silverpeak} abzufragen.

\begin{lstlisting}[language=Typescript, caption={Silverpeak API request}, label={lst:silverpeak-request}]
const username = '...';
const password = '...';
const baseUrl = '...';

function extractCookieValue(setCookieHeader: string, cookieName: string): string | undefined {
    const match = setCookieHeader.match(new RegExp(`${cookieName}=([^;]+)`));
    return match?.[1];
}

const loginResponse = await fetch(`${baseUrl}/gms/rest/authentication/login`, {
    method: 'POST',
    headers: {
        'Content-Type': 'application/json'
    },
    body: JSON.stringify({
        loginType: 0,
        user: username,
        password: password
    })
});

const loginSetCookie = loginResponse.headers.get('set-cookie') ?? '';
const sessionId = extractCookieValue(loginSetCookie, 'gmsSessionID');
const csrfToken = extractCookieValue(loginSetCookie, 'orchCsrfToken');

if (!csrfToken || !sessionId) {
    throw new Error('Login erfolgreich, aber Session-Cookie oder CSRF-Token fehlt.');
}

const cookieHeader = `gmsSessionID=${sessionId}; orchCsrfToken=${csrfToken}`;

const appliancesResponse = await fetch(`${baseUrl}/gms/rest/appliance`, {
    method: 'GET',
    headers: {
        'Cookie': cookieHeader,
        'X-XSRF-Token': csrfToken,
        'Content-Type': 'application/json'
    }
});

const data = await appliancesResponse.json();
console.log(data);
\end{lstlisting}

\section{Grafana}
\label{sec:grafana}

\gls{grafana} kann eingesetzt werden, um Daten verschiedener Systeme grafisch 
aufzubereiten und einheitlich anzuzeigen~\cite{grafana2026about}. Grafana wird 
dabei nicht nur in Unternehmensumgebungen eingesetzt, sondern auch in wissenschaftlichen 
Forschungsinfrastrukturen zur Visualisierung und Überwachung von Betriebs- und 
Messdaten in nahezu Echtzeit \cite{VBondar2025}. Die weite Verbreitung der 
Plattform zeigt sich auch an der Anzahl ihrer Nutzer:innen. Laut eigenen Angaben 
von Grafana Labs wird \gls{grafana} von mehr als 35 Millionen Nutzer:innen weltweit 
genutzt; mehr als 7.000 Unternehmen zählen dabei zu den zahlenden Kund:innen~\cite{grafana2026pressrelease}.

\subsection{Aufbau}
\label{subsec:grafana-buildup}

\gls{grafana} ist in verschiedene Module und Steuerelemente aufgeteilt.
Zu den zentralen Bestandteilen gehören Datenquellen, Dashboards und
Panels~\cite{grafana2026dashboardsoverview}. Des Weiteren stellt \gls{grafana} eine HTTP-basierte
Programmierschnittstelle bereit, über die Funktionen von \gls{grafana}
programmatisch angesprochen werden können~\cite{grafana2026httpapi}.
Darüber hinaus verfügt \gls{grafana} über Funktionen zur Verwaltung von
Benutzer:innen und deren Berechtigungen~\cite{grafana2026usermanagement}.

\subsection{Datenquellen}
\label{subsec:grafana-datasources}

Datenquellen ermöglichen den Abruf und die Verarbeitung von Daten aus unterschiedlichen 
Quellen. \gls{grafana} verfügt bereits über eine Vielzahl integrierter Datenquellen. 
Für weitere Systeme können zusätzliche Datenquellen in Form von Plugins installiert oder 
eigenständig entwickelt werden~\cite{grafana2026datasources}.

Im Unterschied zu den in den folgenden Kapiteln beschriebenen direkten Anfragen an externe
Systeme wie \gls{zabbix}, \gls{silverpeakcompany} oder \gls{merakicompany} erfolgt der Zugriff
auf \gls{grafana}-eigene Datenquellen nicht direkt, sondern über den zentralen
\gls{grafana}-Endpunkt \texttt{/api/ds/query}. Dieser nimmt die Abfrage entgegen, leitet sie
intern an die konfigurierte Datenquelle weiter und gibt das Ergebnis in einem einheitlichen
Datenformat zurück, unabhängig vom darunterliegenden System~\cite{grafana2026httpapi}.

Ein möglicher Aufruf zur Abfrage einer in \gls{grafana} konfigurierten Datenquelle ist in
Codebeispiel~\ref{lst:grafana-datasource-request} dargestellt.

\begin{lstlisting}[language=Typescript, caption={Abfrage einer konfigurierten Datenquelle über die Grafana-API}, label={lst:grafana-datasource-request}]
import { getBackendSrv } from '@grafana/runtime';

async function queryDatasource(datasourceUid: string, rawSql: string) {
    const response = await getBackendSrv().post('/api/ds/query', {
        queries: [
            {
                refId: 'A',
                datasource: { uid: datasourceUid },
                rawSql,
                format: 'table',
            },
        ],
    });

    console.log(response.results.A.frames);
}

queryDatasource('mssql-uid', 'SELECT TOP 10 * FROM dbo.Locations');
\end{lstlisting}

\subsection{Plugins}
\label{subsec:grafana-plugins}

\gls{grafana} bietet die Möglichkeit an Plugins zu installieren und diese zu nutzen~\cite{grafana2026pluginmanagement}.
Darüber hinaus können auch selber Plugins entwickelt und veröffentlicht werden~\cite{grafana2026plugintutorials}.

\subsection{API}
\label{subsec:grafana-api}

\gls{grafana} kann über eine HTTP-API programmatisch angesprochen werden~\cite{grafana2026httpapi}. 
Diese ermöglicht es beispielsweise, Team- oder Nutzerinformationen aus bestehenden 
\gls{grafana}-Systemen abzurufen.

Ein möglicher Aufruf innerhalb eines Plugins ist in Codebeispiel~\ref{lst:grafana-request}
dargestellt.

\begin{lstlisting}[language=Typescript, caption={Abrufen von Teaminformationen über die Grafana-API}, label={lst:grafana-request}] 
import { getBackendSrv } from '@grafana/runtime';

async function loadTeams() {
    const response = await getBackendSrv()
        .get('/api/teams/search', {
            query: '', perpage: 20,
        });
    console.log(response.teams);
}

loadTeams();
\end{lstlisting}

Die Schnittstelle kann mithilfe des \gls{grafana} Plugin SDK für Go erweitert werden, 
um eigene Plugins oder Datenquellen zu entwickeln~\cite{grafana2026plugintutorials,grafana2026backendplugins}.
Ein solches Backend-Plugin läuft dabei als eigenständiger Prozess, mit dem der 
\gls{grafana}-Server über \gls{grpc} kommuniziert~\cite{grafana2026backendplugins}.

Im Beispiel~\ref{lst:grafana-go-datasource} wird die grundlegende Verarbeitung einer 
Datenabfrage innerhalb eines Datenquellen-Plugins dargestellt.

\begin{lstlisting}[language=Go, caption={Minimale Verarbeitung einer Datenabfrage in Go}, label={lst:grafana-go-datasource}]
package plugin

import (
    "context"

    "github.com/grafana/grafana-plugin-sdk-go/backend"
    "github.com/grafana/grafana-plugin-sdk-go/backend/instancemgmt"
)

type Datasource struct{}

func NewDatasource(ctx context.Context, settings backend.DataSourceInstanceSettings) (instancemgmt.Instance, error) {
    return &Datasource{}, nil
}

func (d *Datasource) QueryData(ctx context.Context, req *backend.QueryDataRequest) (*backend.QueryDataResponse, error) {
    response := backend.NewQueryDataResponse()

    for _, query := range req.Queries {
        response.Responses[query.RefID] = backend.DataResponse{}
    }

    return response, nil
}
\end{lstlisting}
