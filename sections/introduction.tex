\section{Initial Situation}

Employees at Primetals Technologies Austria GmbH currently have to access multiple
systems in order to obtain information about the company's IT infrastructure and
identify potential issues. According to employees, relevant information is
distributed across various sources, primarily \gls{mssql} databases and web interfaces,
making infrastructure monitoring time-consuming and inefficient. Employees who
have worked with these systems also reported that important information can
easily be overlooked due to the lack of a centralized overview.

\subsection{Company}

Primetals Technologies Austria GmbH is an international engineering company
specializing in technologies, equipment, and automated solutions for the
metals industry. The company develops solutions for steel production with a
focus on improving productivity, sustainability, and digitalization
~\cite{primetals2026}.

\subsection{Infrastructure landscape}

The infrastructure of Primetals Technologies Austria GmbH consists of multiple
sources that contain information about different company resources. The primary
\gls{mssql} databases store structured information about devices, locations, and
networks through tables and views. Additionally, web applications provide
information about devices, Azure services, and the connection status of different
networks.

\section{Problem Statement}

The current infrastructure requires employees to manually collect data from
independent sources in order to gain a complete understanding of the company's
infrastructure. The manual process consumes time and increases the risk of 
errors during the data analysis. As a result, there is no reliable way to
efficiently monitor the current state of the company's IT infrastructure.

\section{Concept}

The proposed concept is based on a centralized application that collects and
aggregates information from existing sources. The collected data is processed
through a centralized datasource layer, which provides a unified interface for
accessing infrastructure information. Instead of manually accessing multiple 
systems, employees are provided with one centralized visualization that supports
them in identifing issues within the company's technical landscape.

\section{Proposed Solution}

The goal is a \gls{grafana} plugin that implements the Global Infrastructure
Overview (GIO) system. The plugin is divided into multiple layers to separate
data processing, communication, and visualization.

The common layer contains repositories and providers, which process and
aggregate the collected data before it is accessible through the \gls{grafana}
Go API interface.

The datasource layer can be extended to retrieve data from \gls{mssql} databases and
APIs. The collected information is transformed into a unified structure and
forwarded to the visualization layer, which can access the data independently of
the original data structure.

The visualization layer presents the data of Primetals Technologies Austria GmbH
on a world map and detail views for closer information. The view changes based on
zoom and click actions. Additionally, filter and search functions help employees
to locate a problem and analyze it.

Access to \gls{grafana} is secured through the existing authentication and authorization
mechanisms, ensuring that only authorized users can access the plugin.
